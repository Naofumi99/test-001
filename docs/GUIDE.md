# Cursor と GitHub のしくみ・使い方ガイド（初心者向け）

「何をする道具なのか」「なぜその操作をするのか」を、たとえ話つきで説明します。
用語は最初は覚えなくてOK。**意味がなんとなく分かれば十分**です。

---

## 1. まず全体像：3つの登場人物

| 登場人物 | 役割 | 身近なたとえ |
|---------|------|-------------|
| **Cursor** | コードを書く机（AI付き） | 文章を書く「ノート＋アシスタント」 |
| **Git** | 変更を記録するしくみ | 書いた内容の「セーブ機能」 |
| **GitHub** | ネット上の保管・共有場所 | 写真をあげる「クラウド（Googleドライブ的な所）」 |

流れをひとことで言うと：

```
Cursor で書く  →  Git でセーブ  →  GitHub にアップロード
 （手元の机）      （履歴に記録）      （ネットに保存・共有）
```

ゲームで言えば、**Git は「セーブ」**、**GitHub は「セーブデータをクラウドに預ける」**
イメージです。だから「PCが壊れてもデータが残る」「昨日の状態に戻せる」わけです。

---

## 2. Cursor とは（コードを書く机）

- **正体**: プログラムを書くための高機能なエディタ（＝文章作成ソフトのコード版）。
- **特徴**: AIが内蔵されていて、**日本語で質問しながら書ける**。
- 中身は「VS Code」という定番エディタと同じなので、ネットのVS Code解説もそのまま使えます。

### 覚えると便利なショートカット（今は1つだけでOK）
- **`Cmd + L`（Mac）／`Ctrl + L`（Windows）**
  → AIとのチャットが開く。「この行の意味は？」「エラーの直し方は？」と日本語で聞けます。

> 💡 使い方のコツ
> わからないコードを選択して `Cmd/Ctrl + L` →「これを初心者向けに説明して」。
> これだけで、あなた専用の家庭教師になります。

---

## 3. Git と GitHub の用語（意味だけ押さえる）

コードを保存・共有するとき、下の言葉が出てきます。
**丸暗記は不要**。「あぁ、あの操作か」と分かればOKです。

| 用語 | 読み | 意味（かんたんに） | なぜ必要？ |
|------|------|------------------|-----------|
| **リポジトリ** | repository | プロジェクト1個分の入れ物（フォルダ＋履歴） | 作品ごとの保管箱 |
| **クローン** | clone | GitHubにある入れ物を自分のPCにコピーする | 手元で作業するため |
| **コミット** | commit | 変更に名前を付けて記録（セーブ） | 「いつ何を変えたか」を残す |
| **プッシュ** | push | 記録をGitHubへアップロード | ネットに保存・共有する |
| **プル** | pull | GitHubの最新を自分のPCへ取り込む | 他の変更を反映する |
| **ブランチ** | branch | 作業用の枝分かれ | 本体を壊さず安全に試す |

### たとえ話で1本の線に
1. **クローン** … クラウドの箱を机に持ってくる
2. Cursor で編集 … 中身を書き換える
3. **コミット** … 「ここまでやった」と名前を付けてセーブ
4. **プッシュ** … セーブデータをクラウドへ戻す

このプロジェクトはもう GitHub に箱（リポジトリ `Naofumi99/test-001`）があるので、
最初にやるのは **クローン**（机に持ってくる）です。

## 4. 実際の操作：最初の一歩（クローン）

GitHub のプロジェクトを Cursor に取り込みます。方法は2つ。**やりやすい方でOK**。

### 方法A：Cursor の画面だけで完結（おすすめ）
1. Cursor を開く
2. 上部メニュー（またはコマンドパレット `Cmd/Ctrl + Shift + P`）で
   **「Git: Clone」** と入力して選ぶ
3. URL を貼る： `https://github.com/Naofumi99/test-001.git`
4. 保存する場所（PCのフォルダ）を選ぶ → 完了
5. 「開きますか？」と聞かれたら **開く（Open）**

### 方法B：URLを開く
- ブラウザで `https://github.com/Naofumi99/test-001` を開き、
  緑の **「Code」ボタン → 「Open with ...」** から Cursor で開く方法もあります。

> ⚠️ 初回はGitHubへのログイン（サインイン）を求められることがあります。
> 画面の指示どおり「Sign in with GitHub」を押して許可すればOKです。
> ここでつまずいたら、そのままスクショや文言を教えてください。一緒に解決します。

## 5. 実際の操作：毎回くり返す3ステップ（保存の流れ）

Cursor の左側にある **枝わかれのアイコン（Source Control / ソース管理）** を使います。
数字バッジが「変更のたまり具合」です。

```
1. 左の「ソース管理」アイコンを開く
        ↓
2. メッセージ欄に何をしたか書く（例：「入力フォームを追加」）
        ↓
3. 「✓ コミット」ボタン → 続けて「同期／プッシュ」ボタン
        ↓
   GitHub にアップロード完了！
```

| 操作 | Cursor での場所 | やる意味 |
|------|----------------|---------|
| 変更を確認 | ソース管理パネルに変わったファイルが並ぶ | 何を変えたか目で確認 |
| コミット | メッセージを書いて「✓」 | 手元にセーブ |
| プッシュ | 「Sync Changes」/「⋯ → Push」 | GitHubへ反映 |

> 💡 コミットメッセージのコツ
> 「作業内容が一言で分かる日本語」でOK。例：「合計金額の計算を追加」。
> あとで履歴を見たとき、自分が助かります。
